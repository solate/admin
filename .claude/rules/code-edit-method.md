# 代码编辑方式规范

## 规则
修改代码时按以下优先级选择工具：

### 0. Go 文件专属策略：Edit + go fmt（最高优先级）

Go 文件有 `gofmt` 自动格式化，**不需要关心对齐**。使用三步法：

**第一步：Edit 改纯英文代码**
- `old_string` 只选纯英文代码行（忽略中文注释行、跳过对齐空格）
- 只需保证语法结构正确（括号、逗号、花括号匹配），对齐无所谓
- 典型操作：替换函数体、删除字段、插入代码块

```go
// old_string 不需要对齐，只要括号正确
old_string: "review := &model.CustomResourceReview{\nReviewID: reviewID,\n}"
// 即使缩进不对也没关系，go fmt 会修复
```

**第二步：`gofmt -w` 修复格式**
```bash
gofmt -w internal/service/custom_resource_service.go
```

**第三步：补中文注释**
- 用 Edit 工具选纯英文锚点插入中文注释
- 或用 sed 单行替换添加中文注释

**核心优势**：Edit 只需匹配纯英文 → 对齐交给 gofmt → 不再反复修补缩进。

---

### 1. Edit 工具（通用小改动）

**适用条件**：
- `old_string` 选中的文本**完全不含中文**
- 改动范围 ≤ 5 行

**典型场景**：修改 import 语句、函数签名、纯英文赋值、英文注释。

**技巧**：用前后相邻的纯英文代码行做锚点，跳过中间的中文注释行。

### 2. sed 按行号替换（仅限单行含中文改动）

**适用条件（必须同时满足）**：
- 改动范围 = 1 行
- 文件行数 > 200（避免小文件用 sed 过度复杂化）

**典型场景**：大文件中改 1 行含中文的字符串赋值或中文注释。

**用法**：先 Read 确认行号，再用 sed 替换。
```bash
sed -i '' '105s/.*/\t\tdeviceType = constants.DeviceTypeControl/' internal/service/device_service.go
```

**注意**：
- 替换前必须先 Read 确认行号准确
- **禁止用 sed 插入或替换多行代码**（macOS sed 的 `\t` 陷阱）
- macOS 用 `sed -i ''`，Linux 用 `sed -i`

### 3. Write 工具（非 Go 文件的主力，大改动）

**适用条件（满足任一）**：
- 非 Go 文件的大改动（SQL、YAML、Markdown 等）
- Go 文件改动范围 > 20 行且 go fmt 无法解决（极少见）

**用法**：Read 文件 → 修改内容 → Write 写回完整文件。

**可靠性**：100% 成功率，因为不需要字符串匹配，直接覆盖。

---

## 决策流程图

```
需要修改代码
  ↓
是 Go 文件？
  ├─ 是 → Edit 改纯英文代码 → gofmt -w → 补中文注释
  └─ 否 → 改动 ≤ 3 行？
               ├─ 否 → Write（大改动）
               └─ 是 → old_string 能否完全不含中文？
                    ├─ 能 → Edit（纯英文小改动）
                    └─ 不能 → 文件 > 200 行？
                            ├─ 是 → sed 按行号（单行中文）
                            └─ 否 → Write
```
